Data Apa yang Perlu Dilindungi?

Mengapa data perlu dilindungi?
Data adalah aset berharga. Kebocoran data dapat merugikan individu, organisasi, bahkan negara. Perlindungan data bukan hanya tanggung jawab tim IT, tetapi seluruh pengguna sistem.
04 // DATA AT REST

Data yang Sedang Tersimpan

Data at Rest adalah data yang disimpan dalam media penyimpanan dan tidak sedang dipindahkan atau diproses.

💾

Data at Rest (Data Tersimpan)

Data yang sedang tersimpan dalam media penyimpanan seperti hard disk, database, atau perangkat lainnya. Data ini tidak sedang berpindah melalui jaringan.

Contoh:
▸ Database nilai mahasiswa di server kampus
▸ File laporan keuangan di laptop
▸ Database pelanggan di cloud storage
▸ Foto identitas dalam sistem registrasi
Perlindungan: Enkripsi disk, pembatasan akses fisik, password database, backup terenkripsi.
05 // DATA IN TRANSIT

Data yang Sedang Berpindah

Data in Transit adalah data yang sedang dikirim atau dipindahkan melalui jaringan komunikasi.

📡

Data in Transit (Data Berpindah)

Data yang sedang dikirimkan melalui jaringan internet, intranet, atau media komunikasi lainnya. Data ini rentan terhadap serangan penyadapan (sniffing/man-in-the-middle attack).

Contoh:
▸ Username dan password saat login ke website
▸ Data kartu kredit saat transaksi online
▸ Pengiriman file melalui email
▸ OTP yang dikirim ke nomor telepon
Perlindungan: TLS/HTTPS, VPN, enkripsi end-to-end, sertifikat digital.
06 // DATA IN USE

Data yang Sedang Diproses

Data in Use adalah data yang sedang aktif digunakan atau diproses oleh suatu aplikasi atau pengguna.

⚙️

Data in Use (Data Digunakan)

Data yang sedang aktif diproses di memori komputer (RAM) atau sedang digunakan oleh aplikasi. Data ini rentan terhadap serangan yang menarget memori sistem.

Contoh:
▸ Dosen sedang menginput nilai mahasiswa di sistem
▸ Sistem menghitung total transaksi belanja
▸ Mahasiswa membuka halaman nilai di browser
▸ Aplikasi memverifikasi OTP yang dimasukkan
Perlindungan: Enkripsi memori, session timeout, secure coding, pembatasan akses proses.

07-08 // AUTHENTICATION & AUTHORIZATION

Autentikasi vs Otorisasi

Dua konsep penting yang sering dikacaukan, namun memiliki peran yang berbeda dalam sistem keamanan.

🔑

AUTHENTICATION

Autentikasi
"Siapa kamu?"

Proses memverifikasi identitas pengguna sebelum memberikan akses ke sistem.

  • 👤 Username dan Password
  • 👆 Fingerprint (Sidik Jari)
  • 📷 Face Recognition (Wajah)
  • 📱 OTP (One-Time Password)
  • 🔐 MFA (Multi-Factor Auth)
🔓

AUTHORIZATION

Otorisasi
"Apa yang boleh kamu lakukan?"

Proses menentukan hak akses pengguna terhadap sumber daya setelah berhasil login.

  • 🎓 Mahasiswa → melihat nilai sendiri
  • 👨‍🏫 Dosen → mengelola nilai mata kuliah
  • ⚙️ Admin → mengelola data sistem
  • 🚫 Mahasiswa → tidak bisa ubah nilai lain

09 // ACCESS CONTROL & LEAST PRIVILEGE

Kontrol Akses & Hak Minimum

Setiap pengguna hanya diberikan hak akses sesuai kebutuhan tugasnya — tidak lebih, tidak kurang.

Least Privilege (Hak Minimum) — Prinsip yang menyatakan bahwa setiap pengguna hanya diberi hak akses minimum yang diperlukan untuk menjalankan tugasnya. Ini meminimalkan risiko penyalahgunaan akses.

10 // AUDIT TRAIL

📌 Siapa yang mengubah data

11 // STUDI KASUS

Perubahan Nilai di Sistem Akademik

Analisis kejadian nyata menggunakan kerangka CIA Triad untuk mengidentifikasi pelanggaran keamanan.

📋 KASUS:
"Seorang mahasiswa login ke Sistem Akademik Kampus. Beberapa hari kemudian, nilai mata kuliah berubah tanpa sepengetahuan dosen dan mahasiswa lain yang bersangkutan."

📍 Timeline Kejadian

TAHAP 1
LOGIN
Akun mahasiswa digunakan untuk login ke sistem akademik kampus.
TAHAP 2
AKUN DIGUNAKAN
Akun digunakan untuk mengakses data yang berada di luar hak aksesnya.
TAHAP 3
NILAI BERUBAH
Nilai mata kuliah beberapa mahasiswa berubah tanpa persetujuan dosen.
TAHAP 4
INSIDEN DITEMUKAN
Dosen atau admin menemukan adanya perubahan tidak sah melalui laporan atau audit trail.

🔍 Analisis CIA Triad

🔒 CONFIDENTIALITY
Akun atau kredensial kemungkinan diakses oleh pihak yang tidak berwenang. Informasi login bersifat rahasia dan tidak boleh digunakan oleh orang lain.
✅ INTEGRITY
Nilai mata kuliah berubah tanpa izin. Ini adalah pelanggaran integritas — data yang seharusnya akurat dan tidak berubah telah dimanipulasi.
⚡ AVAILABILITY
Periksa apakah sistem tetap dapat diakses atau mengalami gangguan. Availability terganggu hanya jika sistem/data tidak tersedia ketika dibutuhkan.
💡
Catatan: Availability hanya dikatakan terganggu jika sistem atau data tidak tersedia ketika dibutuhkan. Jika sistem masih bisa diakses, masalah utama ada pada Confidentiality dan Integrity.
