Konsep Dasar

Pengertian Struktur Sistem Operasi

Struktur Sistem Operasi adalah cara bagaimana berbagai komponen sistem operasi disusun, diorganisasikan, dan saling berinteraksi untuk menyediakan layanan kepada aplikasi dan pengguna.

Sistem operasi modern tidak dibuat sebagai satu kesatuan monolitik raksasa tanpa batas, melainkan dibagi menjadi subsistem dan modul dengan tugas spesifik.

Catatan Penting: Susunan dan implementasi aktual antar sistem operasi (seperti Linux, Windows, dan macOS) dapat berbeda berdasarkan arsitektur desainnya (monolitik, mikrokernel, hibrida, dll).

Inti Sistem Operasi

Kernel: Pengelola Utama Sumber Daya

🧠 KERNEL

Bagian sentral yang selalu aktif di memori utama selama komputer menyala, memiliki hak istimewa tertinggi untuk mengontrol perangkat keras.

⚡ Penjadwalan CPU

Mengatur giliran proses aplikasi mana yang dieksekusi oleh CPU.

💾 Pengelolaan Memori

Mengalokasikan dan membebaskan ruang memori RAM untuk setiap proses.

🔄 Pengelolaan Proses

Membuat, menghentikan, dan menyinkronkan jalannya proses program.

🛡️ Mekanisme Proteksi

Menegakkan aturan hak akses dan keamanan data antar aplikasi.

User Interface

Shell dan Antarmuka Pengguna (GUI)

Command Line Interface (CLI / Shell)

Text Based

Antarmuka berbasis teks di mana pengguna mengetik perintah (commands) yang kemudian ditafsirkan dan dieksekusi oleh shell (contoh: Bash, Zsh, PowerShell).

user@ubuntu:~$ sudo apt update && apt upgrade
Karakteristik: Cepat, efisien untuk skrip otomatisasi dan administrator sistem.

Graphical User Interface (GUI)

Visual Based

Antarmuka visual menggunakan elemen grafis seperti jendela (window), ikon, menu, dan pointer mouse (WIMP) untuk berinteraksi dengan sistem.

📁
Desktop Windows / GNOME
Klik ikon untuk membuka aplikasi atau file.
Catatan: Shell bukan bagian dari kernel; shell berjalan di ruang pengguna dan menerjemahkan perintah ke system call.
Mekanisme Layanan

System Call (Panggilan Sistem)

Jembatan vital antara program aplikasi dan kernel sistem operasi.

System Call adalah antarmuka pemrogram ke layanan yang disediakan oleh kernel. Ketika aplikasi ingin membuka file, membuat proses baru, atau mengirim data jaringan, aplikasi tidak mengakses hardware secara langsung.

Aplikasi memanggil fungsi pustaka (API seperti Win32 atau POSIX), yang kemudian mengeksekusi instruksi system call.

Tingkat Hak Akses

User Mode dan Kernel Mode

User Mode

Hak Terbatas
  • • Digunakan oleh aplikasi biasa dan program pengguna.
  • • Memiliki akses terbatas terhadap memori dan perangkat keras.
  • • Jika aplikasi crash, sistem keseluruhan tidak ikut runtuh.

Kernel Mode

Hak Istimewa (Privileged)
  • • Digunakan oleh inti kernel dan driver perangkat keras.
  • • Memiliki akses penuh ke seluruh instruksi mesin dan memori.
  • • Kesalahan di mode ini dapat menyebabkan Kernel Panic / BSOD.
💡 Catatan: Perpindahan mode dari User Mode ke Kernel Mode tidak hanya terjadi karena System Call, tetapi juga dipicu oleh Interrupt (interupsi perangkat) dan Exception (error program).
Pengendali Perangkat

Device Driver (Pengendali Perangkat)

Device Driver adalah modul perangkat lunak khusus yang memungkinkan sistem operasi berkomunikasi dan mengendalikan perangkat keras tertentu (seperti printer, GPU, kartu suara, dan SSD).

Driver bertindak sebagai penerjemah universal: mengubah perintah standar sistem operasi menjadi instruksi spesifik yang dipahami oleh chipset hardware tersebut.

Contoh: Driver Printer Epson menerjemahkan dokumen PDF dari komputer menjadi sinyal perintah dot-matrix / inkjet yang akurat.

Fasilitas Sistem

Layanan yang Disediakan Sistem Operasi

🚀 Eksekusi Program

Memuat program ke memori dan menjalankannya hingga selesai.

📁 Operasi File

Membaca, menulis, membuat, dan menghapus file serta direktori.

💬 Komunikasi Antarproses

Memungkinkan pertukaran data antar aplikasi (IPC / sockets).

⚠️ Penanganan Kesalahan

Mendeteksi error pada CPU, memori, atau perangkat I/O.

🔒 Keamanan & Proteksi

Mengontrol akses terhadap sumber daya sistem dan data pengguna.

🌐 Jaringan (Networking)

Mengelola koneksi dan pertukaran paket data antar komputer.

Analisis Kasus Nyata

Studi Kasus: Mencetak Dokumen

Skenario: Seorang mahasiswa menekan tombol "Print" pada aplikasi pengolah kata untuk mencetak tugas makalah ke printer kantor.

Identifikasikan peran masing-masing komponen berikut dalam alur pencetakan tersebut: Aplikasi, System Call, Kernel & Layanan OS, Device Driver, dan Perangkat Keras.

1. Peran Aplikasi: Membuat dokumen dan mengirim perintah cetak awal.
2. System Call: Meminta layanan pembuatan file antrian cetak (print spooler) kepada kernel.
3. Kernel & Layanan OS: Mengatur alokasi proses dan memori untuk tugas pencetakan.
4. Device Driver: Menerjemahkan data cetak ke format byte printer spesifik.
5. Perangkat Keras: Printer fisik menarik kertas dan mencetak dokumen.
